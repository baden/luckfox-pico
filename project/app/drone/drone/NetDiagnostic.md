## Збираю інформацію по тестуванню проблем в роботі мережі.

Промпт для аналізу через ШІ:

```
Є декілька послідовних вузлів в системі передачі даних через інтернет-мережу.
Треба зробити план тестування якості роботи кожного вузла.
Є:
1. IP-камера, з якої забирається відео через rtsp. IP камери: 10.0.0.101. На боці камери нічого запускати не можна, тому треба робити тестування з іншого боку каналу.
2. Є Luckfox, який кабелем підключений до камери. Він через ПО рестрімінгу забирає відео з камери через rtsp. На Luckfox встановлений мінімальний Linux, зібраний через buildroot. Із доступних утіліт: вбудована в busybox утіліта ping, iperf3, mtr,  tcpdump, вбудований в busybox arp, вбудований в busybox netstat, htop.
3. На Luckfox встановлено Wireguard. Наступним кроком треба буде тестувати канал до сервера, як сам канал, так і VPN-тунель, так і VPN-тунель до іншого піра в мережі. Не треба зараз описувати це тестування, просто врахувати в тестуванні.
Шо треба тестувати:
1. Проходження ping-пакетів в обох напрямках. Замір затримки. Тестування при різних розмірах пакетів, для виявлення потенційних проблем з MTU. Бажано отримати статистику чи були вимушені фрагментації пакетів. Треба мати змогу переконатись шо немає проблем з MTU. Треба мати змогу бачити реальне значення затримок, мінімальна, максимальна, jitter.
2. Проходження UDP-пакетів. Аналогічні заміри як по ping, затримки, jitter, доставлення пакетів out of order, небажана фрагментація. Чи є проблема з mtu. Додати тести, які б робили визначення максимального розміру пакетів, при яких виникає фразментація.
3. Замір максимально можливої швидкості передачі UDP в обох напрямках. Визначення проблем з загубленностю UDP-пакетів, порушення порядку, проблеми фразментації.
4. Базові тести TCP, тестування швидкості, проблем з MTU.

Створи перелік тестів для двох сценаріїв:
1. Коли тести виконуються на боці Luckfox, тими інструментами шо є в списку вище, та додатковими вбудованими, або ті, які не складно зібрати через buildroot. На іншому боці камера, в якій тільки є налантований IP, та працюючий сервіс rtsp.
2. Коли тести виконуються на двох Linux пристроях, однин - це Luckfox, інший - це повноцінний компьютер або сервер, на Ubuntu, на якому немає обмежень по використанню інструментів тестування.

```
