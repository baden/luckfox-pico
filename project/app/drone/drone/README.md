# Drone C Application

Реалізація системи керування дроном на чистому C з асинхронною архітектурою pthread, яка повторює функціональність Python версії.

## Архітектура

### Модулі

1. **CRSF (`crsf.h/c`)** - Парсинг CRSF протоколу з UART /dev/ttyS3 на 420000 baud
   - 16 каналів по 11 біт
   - Конвертація значень 174-992-1811 → -1.0..0..1.0
   - Автоматичне перепідключення при розриві

2. **UDP Client (`udp_client.h/c`)** - Клієнт для зв'язку з сервером s.navi.cc:8766
   - Простий JSON парсер для команд joy_update, restart, keep_alive
   - Keep-alive пакети кожні 15 секунд
   - Автоматичне перепідключення

3. **GPIO Control (`gpio_control.h/c`)** - Керування GPIO через sysfs
   - Лебідка: IO1(GPIO1_C7)/IO2(GPIO1_C6) - активний рівень LOW
   - Активатор: IO3(GPIO1_C5)/IO4(GPIO1_C4) - активний рівень LOW  
   - Бузер: GPIO2_A2 - неблокуючі патерни
   - Захист від заборонених комбінацій

4. **PWM Control (`pwm_control.h/c`)** - Керування сервоприводами
   - 2 сервоприводи через /sys/class/pwm/pwmchip5/pwm0, pwmchip6/pwm1
   - Частота 50Hz, duty cycle 0.5-2.5ms
   - Диференціальне керування: left=axis0+axis1, right=axis1-axis0

5. **Main (`main.c`)** - Основна програма з pthread архітектурою
   - **CRSF thread** - читання UART, парсинг пакетів
   - **UDP thread** - обробка мережевих команд
   - **Control thread** - оновлення сервоприводів (20ms)
   - **Watchdog thread** - моніторинг таймаутів

## Пріоритезація каналів керування

1. **CRSF** має пріоритет якщо останні дані < 5 секунд
2. **UDP** активний якщо CRSF неактивний > 5 секунд
3. **Watchdog** плавно згасає до 0 якщо дані відсутні > 1.5 секунди
4. **Auto-disarm** через 3 хвилини без керування

```bash
mkdir -p build && cd build

make -j4
```

## GPIO розпінка (Luckfox Pico Pro)

```
BEEPER (GPIO2_A2)     = bank=2, group=0, X=2  -> pin=66
IO1 Лебідка вгору     = bank=1, group=2, X=7  -> pin=55  
IO2 Лебідка вниз      = bank=1, group=2, X=6  -> pin=54
IO3 Активатор вперед   = bank=1, group=2, X=5  -> pin=53
IO4 Активатор назад    = bank=1, group=2, X=4  -> pin=52
```

Формула: `pin = bank * 32 + (group * 8 + X)`

## Канали CRSF

- Канал 0: Ось X (горизонталь) -1.0..1.0
- Канал 1: Ось Y (вертикаль) -1.0..1.0  
- Канал 2: Лебідка (-0.5=up, 0.5=down)
- Канал 3: Активатор (-0.5=forward, 0.5=backward)
- Канал 4: ARM/DISARM (>0.5=armed)

## UDP JSON протокол

```json
{
  "command": "joy_update",
  "data": {
    "axes": [-0.5, 0.3, -1.0, 0.0],
    "buttons": [1, 0, 0, 0]
  }
}
```

```
command: "keep_alive"    - heartbeat
command: "register"      - реєстрація
command: "restart"       - перезапуск
```

## Особливості реалізації

- **Чистий C** без сторонніх бібліотек
- **Linux sysfs** для GPIO та PWM
- **pthread** багатопоточність з м'ютексами
- **Автоматичне відновлення** при збоїх
- **Неблокуючий бузер** з патернами
- **Пріоритетна система** керування
- **Плавне згасання** сервоприводів при таймауті

## Тестування

Скрипт `test_drone.sh` перевіряє наявність потрібних пристроїв та запускає додаток з необхідними правами.

## Відмінності від Python версії

- Видалено OLED дисплей (буде реалізовано окремо)
- Компактна архітектура з pthread замість threading
- Прямий робота з sysfs замість бібліотек
- Оптимізована обробка CRSF пакетів
- Покращена система обробки помилок
